一、發布內容

Fortinet 在 2026-10-22 發布一組協調式安全更新。對象是 FortiOS、FortiManager、FortiAnalyzer。此發布接在 FortiMail 與 FortiAuthenticator 的近期發布之後。

Fortinet 強烈要求每一位客戶規劃並盡快完成升級。客戶在更新提供後立即處理。對外連網的設備優先。

這些發布修補一批漏洞。此批漏洞由 Fortinet 的 frontier AI-assisted security testing program 找出。

二、這次發布為何不同

Fortinet 已把前沿 AI 模型整合進產品安全測試流程。這些模型分析程式碼路徑、協定處理與設定邏輯。此分析的深度與速度是傳統 fuzzing 與人工審查達不到的。

此工作讓 Fortinet 更有效率地找出漏洞。Fortinet 因此能在惡意行為者發現與利用漏洞之前先修補。Fortinet 稱此為 secure-by-design 承諾的實踐。Fortinet 稱此做法是從源頭找出弱點並關閉弱點。

Fortinet 致謝 Anthropic、OpenAI、Google 與 SpaceX。Fortinet 感謝四方在整個過程中的合作。

Fortinet 同時公開一個含意。同等級的 AI 能力也正變得可供攻擊者使用。開源權重模型進步會加速此事。揭露與利用之間的窗口期持續縮短。Fortinet 預期此窗口期會繼續縮短。

三、為何要立即升級

Fortinet 建議客戶把此發布當成優先變更。客戶不要把此發布當成例行維護週期。四個因素造成此急迫性。

  1. 修補等級高。此批發布含 Critical 與 High 等級的修補。
  2. 武器化速度變快。AI 工具現在能協助攻擊者逆向工程修補。攻擊者可在數小時或數天內做出可用的 exploit。過去需要數週。
  3. Patch diffing 風險存在。更新公開後，修補本身會揭露變更位置。修補位置會暴露潛在的系統弱點。未修補的設備因此成為更容易的目標。
  4. 漏洞可以串聯。AI 有能力把看似無關的低等級漏洞連結起來。串聯結果是更嚴重且可利用的漏洞。

Fortinet 建議客戶先套用暫時緩解。客戶再依優先序完成修補。緩解包含下列做法。客戶限制暴露並以頻外方式管理設備。客戶在可行時把資源移到 VPN 或 SASE 後方。客戶套用 virtual patch。

五、公告時程與雲端版本

公開公告不在發布日提供。Fortinet 把公告排在下一個 Patch Tuesday。日期是 2026-11-10。Fortinet 稱此安排是負責任透明與平衡客戶安全的一部分。公告將發布在 Fortinet PSIRT 頁面。

  • FortiSASE 在 2026-10-22 發布前自動更新。
  • FortiManager Cloud 在 2026-10-22 前可供更新。FortiManager Cloud 可能需要手動更新。
  • 公有雲執行個體的更新正由各雲端夥伴推送。客戶依各夥伴的標準發布流程處理。

六、今天要做的事

客戶今天先準備。客戶在 2026-10-22 發布上線後立即升級。

  1. 盤點。客戶找出每一台 FortiManager 設備與每一個 FortiOS 執行個體。暴露在網際網路上的設備與執行個體優先。
  2. 排維護窗口。客戶把對外系統的變更窗口排在 10 月 22 日到 23 日。
  3. 備份設定。客戶在升級前保存現行設定。
  4. 監控。客戶在修補前後檢查日誌。客戶找異常的管理存取與未核准的設定變更。

七、無法立即升級時的緩解

客戶若無法立即升級，先以下列方式降低暴露。

  • 客戶限制管理介面的來源。HTTPS 與 SSH 只允許可信 IP 位址。客戶也可以在對外介面上停用管理介面。
  • 客戶確認 FortiManager 管理功能無法從網際網路連入。
  • 客戶落實最佳實務。管理帳號使用強且不重複的憑證。所有管理帳號強制啟用 MFA。

這些步驟降低風險。這些步驟不取代及時升級。

八、Fortinet 的承諾

Fortinet 稱客戶在下列情況下得到最好的保護。廠商主動找出漏洞並修補。廠商以負責任的方式揭露。Fortinet 稱在自家測試使用前沿 AI 是另一種走在攻擊者前面的方法。攻擊者也在用同一批工具。Fortinet 稱會把此方法繼續用在整個 Fortinet 產品組合。Fortinet 稱會以安全透明的精神與客戶分享發現。

客戶需要升級協助時聯絡 Fortinet 技術支援或客戶團隊。客戶可訂閱 FortiGuard PSIRT 公告。訂閱後可取得發布日的細節。
